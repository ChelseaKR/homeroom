| RR-05 | The keyboard and screen-reader walkthrough in each language, and the narrow-screen reflow check, have not been performed. | RR-06 | The Spanish pages have been reviewed only by their author. | RR-07 | A model sentence that is wrong, invented, or judgmental reaches a family through the ask layer (ADR 0003): a number the state never published, a withheld cell narrated as zero, a comparison across different bases, a "good school" in any wording, or text produced by an injected instruction | Medium | High | Chelsea Kelly-Reif | One school per request, so no cross-school ranking is possible; every claim must cite a record or corpus passage and is verified programmatically (numbers, withheld cells, comparison direction, verbatim quotes) before display; unverifiable claims withheld and counted; fixed, reviewed refusal strings; an independent judgment-language guard over every model sentence in both languages; five committed evaluation suites with provenance-stamped results | Track -- no deployment until the ranking-refusal and suppression suites have a live run recorded at zero on the model that would be deployed, and a person has read a sample of real answers in each language | 2026-09-21 |
| RR-08 | Spanish narration from the ask layer is model output reviewed by nobody; a correct English answer and a subtly wrong Spanish one would pass every automated gate | Medium | Medium | Chelsea Kelly-Reif | The verifier runs the same checks in both languages (numbers, withheld-cell phrasing, judgment lexicon); the fixed strings around the narration come from the parity-gated catalogs; Spanish output is labeled AI-translated and unreviewed on the page; Spanish cases sit in every evaluation suite | Track -- sibling of RR-06; closes only when a Spanish reader reviews a sample of real answers | 2026-09-21 |
| RR-09 | The ask layer depends on a third-party model provider for cost, availability, and behaviour; a deployed service could run up a bill or go dark, and a model change could shift evaluation results without any code change | Medium | Medium | Chelsea Kelly-Reif | Per-client rate limit and hard daily cap in the service; fail-closed to the static page on any provider error or 429; prompt caching on the stable system prompt; the deployment shape is cost-bounded and, as of 2026-08-22, applied at the envelope the owner approved: reserved concurrency 2, a daily cap of 400 model calls, six requests per client per minute, and a CloudWatch alarm at 400 daily invocations to an in-stack SNS topic. No address is subscribed to that topic yet, so the alarm records its state and notifies nobody -- that is the open end of this control. Evaluation results name the exact model and are re-run on any model change | Accepted at the approved envelope (2026-08-22). Two things still open: an alert address on the SNS topic, and the fact that the daily cap is per warm container rather than a shared ledger, so the worst case is reserved-concurrency-many containers each spending it | 2026-09-21 |
